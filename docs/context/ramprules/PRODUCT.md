# Product

## Platform

web

## Users

**Primary — and the tie-breaker on every design call: a software developer who
has been told to "collect FedRAMP evidence on AWS."** They have a terminal open
in the other window and the AWS console in a third. They did not choose
compliance work and they are not a compliance specialist; they have been handed
a certification target and need to know, concretely, which AWS calls to run,
how often, and what each one proves. Their working environment is dark and
text-dense, and they move by keyboard.

**Second, real, and not to be designed against: the GRC / compliance reader.**
They do not run the commands; they assemble the package. They arrive at a
specific artifact by permalink, and their destination is frequently paper — a
PDF attached to a ticket or folded into an SDR. Confirmed as secondary: where
the two audiences conflict, the developer wins.

**Third: agents and crawlers.** A model asked the same question the developer
was asked should be able to read this dataset without HTML-stripping. This is a
stated audience with shipped surfaces (`/api/*`, `/llms.txt`, `/md/*`), not an
afterthought.

## Product Purpose

Turn "you owe FedRAMP evidence" into a scoped, copy-pasteable collection plan.

The visitor states a certification class once (b ≈ Low, c ≈ Moderate, d ≈ High)
and gets back: every piece of evidence that class owes, the AWS call that
fetches it, the cadence the rules demand, the control the call proves — and an
honest register of what no API can prove and must be written by a human.

Success is the developer leaving with commands they can run, and a defensible
trace from each command back to the control it satisfies.

## Positioning

**One dataset, joined — where the market ships three disconnected ones.**

FedRAMP 20x Key Security Indicators, Rev5 control baselines, and authored AWS
evidence recipes exist as separate documents in the world. This product holds
them as a single index in which every join is addressable: an indicator reaches
controls, a control is reached by recipes, a recipe cites the services it calls
and the requirements it traces to. Every entity is a permalink; every number on
every screen is a JSON export; every derived slice is regenerated by a build
step and gated by a freshness test.

Two verbs the product owns and repeats: **fetch** (the AWS call) and **map**
(what it satisfies, traced to the control).

The claim a neighbouring product cannot truthfully copy: the residue is kept
in. Coverage is reported honestly, including the controls nothing reaches and
the evidence no API can produce.

## Operating Context

- Read beside a terminal and the AWS console, in a dark room, during
  implementation work — not in a compliance review meeting.
- Entered three ways: the guided flow from the home page, a deep permalink
  (`/control/AC-02`, `/ksi/…`, `/collect/…`) arrived at from a ticket or a
  search result, and `curl` / an agent hitting the JSON or `.md` twin.
- Navigated by keyboard: `⌘K` global search palette, `j`/`k` row walking.
- Two routes exit to paper as real compliance artefacts: `/plan/[class]` and
  `/collect/[recipeId]`. A printed `/collect/[id]` **is** an evidence-collection
  SOP. Print is a supported output, not a browser accident.
- Preferences persist locally (certification class, AWS partition), so a
  returning reader is not re-asked what they already stated.

## Capabilities and Constraints

**Shipped surfaces.** A three-verb spine — **Scope** (`/map`, `/control/[id]`,
`/ksi/[id]`) → **Plan** (`/plan/[class]` and its themes and narrative) →
**Collect** (`/collect`, `/collect/[recipeId]`) — plus eight reference lenses
(coverage, family heatmap, indicator weight, readiness, obligation clock,
crosswalk, evidence planner, glossary, "who it binds", nomenclature) demoted
behind a Reference menu, and machine exits (`/api/[slice]`, `/md/[kind]/[id]`,
`/llms.txt`, sitemap, robots).

**Stack.** Next.js 16 App Router (a version with breaking changes from
training-data conventions — read `node_modules/next/dist/docs/` before writing
Next code), React 19, Tailwind v4 (CSS-first `@theme`), Base UI primitives,
`next-themes`, `@xyflow/react` for the entity graph. pnpm.

**Data is committed build output.** `data/derived/` and `docs/DATASET-FACTS.md`
are generated by `pnpm derive` and read by the site, the JSON API and the
tests. Any change under `data/overlays/` or `lib/fedramp/` requires
`pnpm derive && pnpm test` and the rewritten slices committed with it.

**Nine gates, in order:** `test · validate · gen:types · derive · typecheck ·
lint · format:check · build`, then `test:a11y` (Playwright + axe over
`e2e/routes.ts`, failing on serious/critical, plus 360px catalog assertions).
All nine must stay green. Design changes are subject to them.

**Never write a count into prose.** Recipe, theme and control totals live in
the data and are rendered from it. A sentence stating one is true for a day.

**Design tokens are data under test.** `lib/design/contrast.test.ts` parses
`app/globals.css` and asserts token pairs against WCAG 2.2 AA in both themes.
A token is only as tested as its surfaces: when a token starts being printed on
a new surface, that pair is added to the test.

## Brand Commitments

- Name: **FedRAMP Rules Hub**, at `ramprules.com`.
- Two-verb vocabulary — **fetch** and **map** — used consistently in copy.
- Voice: precise, plain, unhedged; states absences as facts rather than hiding
  them. Prose explains *why* a decision was made, in the artefact itself. This
  voice is confirmed and is not to be replaced with marketing register.
- No existing logo, wordmark, illustration set, or brand palette. The current
  visual layer is a stock component-library default and carries **no** identity
  commitment — it is evidence of what the product is, not authority over what
  it becomes.

## Evidence on Hand

- The real dataset: `docs/fedramp-consolidated-rules.json` with its schema, the
  derived slices in `data/derived/`, the authored AWS recipe overlay in
  `data/overlays/`. Every number, id, theme and command shown in the product is
  real and rendered from this. **Nothing in this product needs synthetic
  demonstration data, and none may be introduced.**
- Prior analysis to preserve, not repeat: `docs/ui-ux-plan.md` and
  `docs/ui-ux-plan-v2.md` (two shipped IA/accessibility passes),
  `docs/NOMENCLATURE.md`, `TODOS.md` (deferred work, each entry saying why).
- Absent, and not to be fabricated: pricing, customers, testimonials,
  benchmarks, adoption numbers, certification claims, and any assertion that
  this product satisfies an audit.

## Product Principles

1. **The developer is the tie-breaker.** When the compliance reader and the
   implementer want different things, build for the person with the terminal.
2. **Every number is rendered, never typed.** If a fact can rot, it comes from
   the data or it does not ship.
3. **Keep the residue in.** Uncovered controls, narrative-only evidence and
   partition caveats are load-bearing product, not blemishes to hide.
4. **Every entity is addressable, by a human and by a machine.** A permalink, a
   JSON slice and a markdown twin for the same fact.
5. **A claim in prose must be checkable in the tree.** Explain the why where the
   decision lives.

## Accessibility & Inclusion

WCAG 2.2 AA is a shipped, enforced requirement, not an aspiration: contrast
pairs are unit-tested against `app/globals.css`, and axe runs over every route
in CI failing on serious/critical. Additional established requirements: a
visible focus treatment on everything focusable that is never removed, a skip
link, a `<main>` landmark on every route, full keyboard operation including row
navigation, colour never used as the only channel (semantic badges carry a
glyph), a 12px type floor, `prefers-reduced-motion` honoured, and a 360px
minimum viewport with the primary navigation reachable by thumb.
